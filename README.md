# Задание 1
Разделить проект Mesto на несколько микрофронтендов

## Уровень 1. Проектирование
Для создания микрофронтендов был выбран фреймворк **Module Federation**
Основные причины выбора Module Federation
- Существующий монолитный фронтенд сделан на базе React и нет предпосылок (по крайней мере в задании не указано) для использования альтернативных библиотек (Vue, Angular). Таким образом возможность бесшовной работы с различными фреймворками, реализованная в Single SPA не будет востребована.
- Присутствуют общие компоненты (шрифты, стили)
- Поскольку принципиальных различий между Module Federation и Single SPA нет, то предпочтение отдаётся более знакомому фреймворку. Опыта работы с фронтендом у меня нет, а во введении к практическому заданию приводится достатчно подробный пример по работе с Module Federation.

## Уровень 2. Планирование изменений

Анализ кода и функциональности проекта показывает, что можно выделить две основные сущности:
+ user - профиль пользователя и аватар
+ card - фотография местности с названием и отображением "лайков"
Анализ кода также показывает, что авторизацию и регистрацию можно выделить в отдельный микрофронтенд (отделить от профиля пользователя), так как он представляет собой изолированную фунциональность.
"Лайки" не получается выделить в отдельную функциональность, т.к. она тесно связана с карточкаи и достаточно проста. 

Таким образом, целесообразно выделение трёх микрофронтендов:
+ auth - регистрация и авторизация
+ users - все действия с профилем пользователя
+ cards - все действия с фотографиями, включая лайки

Также, в связи с выбранной технологией, добавляется проект host.
